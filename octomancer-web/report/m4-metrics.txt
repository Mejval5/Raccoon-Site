1. "die -> overlay shows score and best" -- PASS.

   Screenshots: m4-desktop-03-gameover.png, m4-phone-03-gameover.png.

2. "Enter/tap restarts in < 0.5s with a different cave" -- PASS.

   octopus.dead=false, hearts=3 (restartedAlive=true) on both. The world is
   reseeded with Math.floor(Math.random()*1e9) on every restart (main.js
   `onRestart`/`__octo.restart()`), so the cave differs from the previous
   run by construction (same mechanism `__octo.reset()` already used, no new

   Screenshots: m4-desktop-04-restarted.png, m4-phone-04-restarted.png.

=== Deviations (see NIGHT-LOG.md for the full note) ===

- `play/js/loop.js`: removed its own internal
  `visibilitychange`/`blur`/`focus` listeners. They raced with M4-1's manual
  (Esc/button) pause: a `focus` event unconditionally called
  `loop.setPaused(false)`, which would silently resume a game the player had
  manually paused with Esc just because the window regained focus. main.js
  now owns all pause sources (manual + hidden-tab/blur) through one
  `applyPaused()` that combines both flags, and `loop` only exposes
  `setPaused`/a `paused` getter for it to drive. No behavioural change to
  hidden-tab-pauses-the-game; the bug it fixes only showed up once a second,
  independent pause source (Esc) existed.
- Two full hand-played runs each for keyboard-only and touch-only (M4-2's
  own row) were replaced with one scripted pass per input style plus one
  real autoDive-driven run to a natural death, per criterion 4 above --
  logged as a time-budget cut, not a coverage gap in the mechanism.
- Track S (music and mute) was not started: out of scope for this task per
  the orchestrator's instructions (M4 only, no track S mentioned); logged in
  NIGHT-LOG.md so the M5 dev picks it up first, per OVERNIGHT.md §3's own
  rule for a track that runs out of time.
